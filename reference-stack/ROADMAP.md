# Reference stack · roadmap

A public, runnable reproduction of the patterns in the case studies, on synthetic data, written from scratch
for this portfolio (no client code). It exists so a reviewer can clone it and see the practices run, not just
read about them. It lives in this directory and grows wave by wave; [README.md](README.md) documents what runs
today.

## Acceptance criteria (EARS, each with its verification)

- **AC-1** The project SHALL build from a fresh clone with `pip install -r requirements.txt && dbt build` in under
  two minutes on a laptop. → verification: `timeout 120 dbt build` in the CI job. **Met in wave 1** (seconds
  locally; see the workflow run for the CI time).
- **AC-2** WHEN a Gold column named in `contract.yml` is removed or retyped, the contract check SHALL fail the PR.
  → verification: a fixture PR in the test suite of `contract_sync.py`. Wave 2. (Today dbt's own enforced contract
  in `_gold.yml` fails the build when a Gold column changes type or disappears.)
- **AC-3** WHEN the engine changes and the output does not, the shadow build SHALL report zero diff per channel;
  WHEN a number changes, it SHALL list the channel, the SKU count and the delta. → verification: two fixture
  commits in CI. Wave 3.
- **AC-4** IF a PR exceeds 300 counted lines without the `large-pr` label, THEN `pr-size` SHALL fail with the
  count. → verification: a fixture branch. Wave 5.
- **AC-5** The closure sensor SHALL select exactly the assets downstream of the changed table, traversing but
  not selecting ephemeral models. → verification: pytest over a stub manifest. Wave 4.
- **AC-6** The AI review job SHALL end with a notice and no cost when the key is absent. → verification: CI run
  on a fork. Wave 5.
- **AC-7** The README SHALL carry the architecture diagram and a table of which case-study pattern each directory
  reproduces. **Met in wave 1** for what exists; extended with each wave.
- **AC-8** WHEN a second `dbt build` runs on the same seeds, the Gold tables SHALL be identical. → verification:
  the CI job builds twice and compares the committed samples with the second build. **Met in wave 1.**
